# نظام VICTORIA Logistics ERP — قطاع إيجاز للنقليات

**VICTORIA Logistics ERP** هو تطبيق لإدارة عمليات النقل والرحلات والعملاء والسائقين والشاحنات والصيانة والتحصيلات والمصروفات والتقارير. الواجهة عربية وتدعم الاستخدام المحلي على جهاز Android.

## حالة التشغيل الحالية

- **تطبيق Android:** يُبنى عبر GitHub Actions من فرع `main`.
- **التخزين المحلي:** يستخدم IndexedDB وLocalStorage. السعة الفعلية يحددها الجهاز ونظام Android وWebView؛ لا توجد سعة مضمونة أو غير محدودة.
- **المزامنة المركزية:** غير مفعّلة تلقائيًا. يلزم نشر الخادم المركزي وإعداد أسرار الإنتاج ورابط الخادم ثم اختبار المزامنة قبل وصف النظام بأنه متعدد الأجهزة.
- **الأمان:** شاشة الإعداد الأولي تُطلب للحساب الافتراضي، وتُخزّن كلمات المرور المحلية الجديدة على هيئة salted hashes عندما تتوفر واجهة التشفير. يجب اختبارها على أجهزة العميل قبل الإنتاج.
- **المحاسبة:** توجد وظائف تشغيلية للتحصيلات والمصروفات وأرصدة الرحلات والتقارير. لا تعتبر هذه النسخة نظام دفتر أستاذ عام مزدوج القيد حتى يتم استكمال واختبار شجرة الحسابات والقيود المتوازنة ومدين/دائن وميزان المراجعة.
- **هوية العميل:** حقول الاتصال والبيانات القانونية تبدأ فارغة عمدًا؛ أدخل البيانات الرسمية المعتمدة قبل إصدار مستندات للعميل.

## بناء وتنزيل APK

1. افتح [GitHub Actions](https://github.com/jovanexpress713-jpg/EJAZ/actions).
2. افتح أحدث عملية بناء عليها علامة نجاح خضراء.
3. نزّل Artifact باسم `VICTORIA-Logistics-ERP-APK-v1.2.0`.
4. فك الضغط وثبّت ملف APK على جهاز اختبار.
5. اختبر تسجيل الدخول والإعداد الأولي وإضافة رحلة وتعديلها وسندات القبض والصرف والتقارير والنسخ الاحتياطي والاستعادة وإعادة تشغيل التطبيق قبل إدخال بيانات حقيقية.

> ملاحظة: البناء الحالي ينتج APK موقّعًا بمفتاح debug. للتسليم الإنتاجي مع ضمان إمكانية تثبيت التحديثات مستقبلًا، يجب إنشاء مفتاح توقيع release خاص والاحتفاظ به خارج المستودع وإعداد أسراره في GitHub Actions. لا ترفع ملف المفتاح أو كلمات مروره إلى GitHub.

## إعداد الخادم المركزي الاختياري

1. انسخ `.env.example` إلى `.env` على خادم خاص.
2. عيّن `JWT_SECRET` و`OWNER_SETUP_KEY` إلى قيم عشوائية قوية وفريدة؛ لا تستخدم القيم التوضيحية كما هي.
3. لا تنشر الخادم على الإنترنت قبل إعداد HTTPS وجدار حماية وقرص دائم للبيانات والنسخ الاحتياطية.
4. أدخل مفتاح التهيئة لمرة واحدة في شاشة إعداد المالك، ثم اختبر تسجيل الدخول والمزامنة من جهازين ببيانات اختبار.
5. لا تعتبر الاتصال ناجحًا إلا بعد التحقق من حالة الخادم ونجاح دفع البيانات وسحبها فعليًا.

## النسخ الاحتياطي

- صدّر نسخة احتياطية قبل تحديث التطبيق أو نقل البيانات إلى جهاز جديد.
- اختبر استعادة النسخة على تثبيت منفصل وتحقق من عدد الرحلات والعملاء والتحصيلات والمصروفات.
- لا تحذف بيانات التطبيق أو تزل التطبيق المثبت قبل التحقق من النسخة الاحتياطية.
